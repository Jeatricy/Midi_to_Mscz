# MIDI 标准化 → MuseScore 钢琴谱

这个工具用于整理 Song Master Pro 5 等扒谱软件导出的 `.mid` / `.midi`：校正整体演奏延迟、过滤弱力度误判、识别倚音、严格琶音、区域性摇摆和常见比例连音等非拍点语义，再把多个声部分配并合并到钢琴大谱表，最终生成可在 MuseScore 中继续编辑的 `.mscz`。

它的目标是得到比“直接把原始 MIDI 导入 MuseScore”更整洁、更容易人工校对的谱面。节奏识别采用启发式规则，不保证与原曲或参考谱逐音完全一致；复杂段落仍可能需要在 MuseScore 中修订。

## 主要功能

- 一次导入一个或多个 MIDI，并读取文件内的全部 MIDI 轨道。
- 每个文件独立分配到高音或低音谱表，并固定成为该谱表中的一个声部；分到同一谱表的多个文件只共享时间线，彼此不会合并成一个声部或同一个和弦。
- 同一 MIDI 内无论原始 note-off 过早还是因踏板而过晚，都按单声部处理：一次攻击（包括同起的多个音）统一延续到下一次攻击，攻击之间不插入休止；踏板/混响尾音则在该边界截断。
- 每个文件可独立升降八度、额外按半音移调、设置最低力度和整轨拍偏移。
- 删除力度严格低于阈值的音，减少扒谱时产生的弱音误判。
- 自动校正常见的固定演奏延迟，并可裁剪所有输入共有的前导空白。
- 先判断常见非拍点语义，再量化普通节奏，避免把倚音、琶音、摇摆或比例连音一律压到二进制拍点。
- 通用比例连音模型当前重点处理 `2:3`、`3:2`、`4:3`、`5:3`、`5:4`、`6:4`、`7:4`、`7:8`、`9:8`、`11:8`、`12:8` 和 `13:8`（实际音数 : 正常音数）；输出层可写入任意 `actual:normal` 比例。
- 对快速装饰音采用保守策略：只折叠严格高置信度颤音；其他装饰或自由速度片段不会被猜成专用记号，但仍会走普通量化，必须人工复核。
- 自动分析实际音高内容来选择调号与大小调，并按该调号重新拼写音名；不会再因为输入 MIDI 的错误调号标签而默认输出 C 大调。
- 自动读取并保留速度时间线与临时拍号变化：细小 BPM 抖动会被平滑，持续的真实变速会写入谱面与播放信息。
- 识别 MIDI 中编码的弱起；没有可靠拍号事件时保守采用 4/4，并把拍号列为人工复核项。
- 输出一个乐器为钢琴、包含高低音谱表的 MuseScore 文件。
- 转换报告会列出读入、保留、过滤、移调、越界和截短踏板尾音的数量；所有自动解释的特殊节奏和无法唯一量化的位置都会汇总为“人工复核小节”，转换不会停下来等待确认。

## 处理原则

处理顺序大致如下：

1. 读取每个 MIDI 的音符起止、力度、速度、拍号和调号事件，并完成 note-on / note-off 配对。
2. 应用每文件力度阈值、移调和拍偏移。移调后超出 MIDI 0–127 的音会删除；超出标准钢琴 A0–C8 的音会保留但给出提示。
3. 把各文件映射到指定谱表；一个 MIDI 固定映射为一个 MuseScore 声部，同谱表不同文件绝不交叉合并。
4. 结合音符内容和 MIDI 元数据分析调号，整理速度/拍号变化与弱起；处理共同前导与固定延迟，再按优先级判断非拍点语义。每个文件内部按攻击序列统一和弦时值，并把踏板造成的尾音截到下一攻击。
5. 按识别出的调号重新选择升降号音名，写出带动态速度、临时变拍和弱起的 MusicXML 4.0 钢琴大谱表，再调用 MuseScore 保存为 `.mscz`。

若比例连音在组边界结束、而同一 MIDI 的下一次攻击更晚，末音会在组边界拆开：连音内部分保持正确比例，组外以同音延音线持续到下一次攻击。因此既不会把连音括号拉坏，也不会在中间插入休止。

几个容易混淆的概念：

- **固定延迟**：自动校正针对整段演奏相对于节拍网格的共同偏差，只移动一个稳定的时间偏置。它不会对某一轨做时间拉伸，也不能修复随时间逐渐增大的轨道漂移。每文件“时间对齐”适合手动对齐某个声部；正数向后移，负数向前移。
- **普通量化**：依据“最小音符”选择允许的二进制网格，并同时整理起点与时值。`1/8` 最保守，`1/16` 通常适合作为起点，`1/32` 能保留更多细节，也更容易保留扒谱噪声。若两个真实攻击会被吸到同一个普通格点，程序会保留两次攻击并临时细分到可准确记谱的 128 分音符网格，同时把所在小节列入人工复核；不会合并攻击，也不会用任意小数时值诱发 MuseScore 补入休止。
- **比例连音**：比较一组连续攻击在多种普通二进制脉冲和多个 `实际音数:正常音数` 模型下的整体误差。当前重点为 `2:3`、`3:2`、`4:3`、`5:3`、`5:4`、`6:4`、`7:4`、`7:8`、`9:8`、`11:8`、`12:8`、`13:8`；只有组边界、槽位、单声部结构和误差改善都足够明确时才自动采用，并写出 MusicXML 的 `time-modification` 与连音起止记号。`--tuplets` 控制所有这些比例，不再只表示三连音。MusicXML 输出层本身支持任意整数比例，但复杂、嵌套或比例不明的连音不会凭音符数量硬猜。
- **倚音与倚音串**：检查紧邻稳定主音的一个或多个短音。高置信度候选写成不占普通谱面时值的 MusicXML grace note；短音也可能是真实的快速旋律，因此边界不明确时不会自动折叠。
- **严格琶音**：在普通和弦合并前检查短时间内方向明确、时值有明显重叠的连续触发。高置信度组会合并为带上行或下行琶音记号的和弦；两音滚奏、快速音阶和经过音较易混淆，因此判定刻意保守。
- **摇摆 / Shuffle**：只有连续多个拍反复出现、同拍同时具有正拍和后半拍证据的稳定长短细分才自动采用，而不是把孤立长短对误写成三连音。高置信度结果按区域保留直写谱面，并在区域起止写入 `Swing` / `Straight` 文字和 MusicXML 播放语义；不会强行套用到整首曲子。
- **快速装饰与自由速度**：目前只把至少六次、间隔稳定、严格 ABAB 邻音交替的高置信度音群折叠成颤音。波音、回音、震音、rubato、fermata、cadenza 等仅凭 MIDI 时间往往无法唯一确定，当前不会自动生成这些专用记号，仍需在 MuseScore 中复核或补写。
- **速度平滑**：自动模式优先得到可读的稳定速度，避免把扒谱 MIDI 中细碎的 BPM 抖动原样变成密集速度变化；持续的真实变速仍会保留。手动填写 BPM 时以该固定值为准。默认平滑可通过 Python API 配置，当前 WebUI 和 CLI 不单独暴露该开关。
- **调号与音名拼写**：调号不会把声音移高或移低，它决定谱号旁固定的升降号以及同一个琴键写成 C♯ 还是 D♭。自动模式以实际音高分布为主，MIDI 自带调号只作为参考；手动换调号时也会重新选择更自然的升降号写法。
- **拍号与弱起**：拍号决定每小节长度和重拍位置。自动模式会保留 MIDI 中途的 3/4、5/4 等临时变拍；开头短小节若是进入完整拍号前的部分小节，会写成弱起，而不是假的临时拍号。

非拍点语义遵循“先保护、后量化”的优先级：严格快速装饰与倚音 → 严格琶音 → 区域性摇摆 → 比例连音 → 普通二进制量化。分类精确到 MIDI 来源和实际音符，另一个 stem 恰好同拍的长音不会连带变成倚音、连音或 Swing。只有高置信度结果才会自动改写为专用记谱语义；会导致两个攻击合并的高残差未知片段则保留展开起点，复杂或自由速度段仍必须人工复核。

| 识别结果 | 高置信度时的自动处理 | 证据不足时 |
| --- | --- | --- |
| 通用比例连音 | 当前重点识别 2–13 音中的常见比例（含五、七、九、十一、十二、十三连音），写入比例时值和连音记号 | 保留展开音符，不凭音符数量猜测比例 |
| 倚音、倚音串 | 附着到稳定主音，写成 grace note | 保留为实际短音 |
| 严格琶音 | 合并为和弦并写上行/下行琶音记号 | 保留各次攻击，不把音阶误折叠成和弦 |
| 区域性摇摆 / Shuffle | 保持直写音符，并在连续区域写入 Swing / Straight 文字与播放语义 | 不根据孤立长短对推断 swing |
| 快速装饰、自由速度 | 严格稳定的 ABAB 邻音交替可写成颤音 | 其他类型不自动生成专用记号，按普通量化输出并要求人工复核 |

这里的“识别”不是从 MIDI 中读取现成的乐谱标记。普通 MIDI 通常只包含音高、起止时间、力度和少量控制事件，同一组时间数据可能同时解释成倚音、很短的实音、琶音、连音、摇摆或演奏误差。因此工具无法仅凭 MIDI 唯一还原作曲者意图，阈值与优先级只能降低误判，不能消除人工校对。

## 环境要求

- Python 3.10 或更高版本。
- Python 依赖 `mido`；执行下面的安装命令会自动安装。
- MuseScore 4（推荐）。程序也会尝试寻找 MuseScore 3，但输出效果以本机 MuseScore 的 MusicXML 导入行为为准。
- 任意现代浏览器。WebUI 只在本机 `127.0.0.1` 临时端口运行，不会把 MIDI 上传到互联网。

MuseScore 是生成 `.mscz` 的必要依赖。程序按以下方式寻找它：Python API 显式路径、环境变量 `MUSESCORE_PATH`、系统 `PATH`，以及常见 Windows 安装位置。若没有装在默认位置，可在 PowerShell 当前会话中设置：

```powershell
$env:MUSESCORE_PATH = "D:\Apps\MuseScore 4\bin\MuseScore4.exe"
```

## 安装与启动

在项目目录打开 PowerShell：

```powershell
py -3 -m venv .venv
.\.venv\Scripts\python.exe -m pip install --upgrade pip
.\.venv\Scripts\python.exe -m pip install -e .
```

Windows 直接双击 `run_webui.pyw`。它由已安装且带签名的 Python 启动，不经过批处理或 PowerShell；这也更不容易触发安全软件对脚本启动链的拦截。也可以从终端启动：

```powershell
.\.venv\Scripts\python.exe -m midi_to_mscz
```

安装为可编辑包后，也可用以下命令打开界面：

```powershell
midi-to-mscz --gui
```

## WebUI 使用

1. 拖入或选择一个或多个 `.mid` / `.midi` 文件。
2. 为每个文件选择高音或低音谱表，并按需调整八度、额外移调、力度阈值和时间对齐；看不懂的设置可点旁边的 `?` 查看例子。
3. BPM、拍号和调号第一次都建议保持“自动”，最小音符先用 `1/16`；高级节奏保护保持默认即可。
4. 选择保存文件夹和文件名，再点击“开始转换”。转换完成后 `.mscz` 会直接写入该文件夹，不经过浏览器下载。
5. 用 MuseScore 打开结果，按页面给出的“人工复核小节”检查低置信度位置。

转换完成后，日志和结果弹窗会单独列出“人工复核小节”。这些位置已经保留在输出 MSCZ 中，程序不会暂停询问；直接在 MuseScore 中按列出的编号修改即可。报告也会显示有多少个踏板/混响尾音被截到下一攻击。

同一谱表可以分配多个 MIDI。例如，人声与另一条旋律都放到高音谱表时，会分别成为 voice 1、voice 2，但仍属于同一个 Piano part。MuseScore 每个谱表最多四个声部，因此一个谱表最多分配四个 MIDI；超过时程序会明确报错，请把部分文件改分到另一谱表。

## 每文件设置

| 设置 | 作用 | WebUI 范围 |
| --- | --- | --- |
| 谱表 | 指定整个 MIDI 放入高音或低音谱表；不会拆分文件 | 高音 / 低音 |
| 升降八度 | 整条 MIDI 每个音移动 12 个半音的整数倍 | -3 到 +3 |
| 额外移调（半音） | 在八度移调之外改变实际音高；+1 等于升高一个琴键 | -11 到 +11 |
| 最低力度 | 删除力度严格小于此值的音 | 1 到 127 |
| 时间对齐（四分音符拍） | 整条 MIDI 在共同时间线上前后移动；+0.5 表示延后一个八分音符 | 可为小数或负数 |

阈值为 `1` 时，正常的 MIDI note-on 力度不会因为该设置被删除；若仍有很多幽灵音，可逐步提高到 `5`、`10` 或更高并对照试听。不同扒谱声部的力度分布可能差异很大，因此最好逐文件设置。

## 全局记谱设置

- **BPM**：自动模式合并多个输入的速度事件、过滤约 1% 的细碎抖动，并保留持续的真实变速；手动模式用 20–400 的固定值覆盖全曲。BPM 指每分钟四分音符拍数。
- **拍号**：自动模式读取并保留 MIDI 中途的临时变拍。若源文件完全没有可靠拍号信息，仅凭攻击时间无法唯一判断 3/4 与 6/8 等含义，程序会保守使用 4/4 并提示复核；若扒谱软件只写了开头一个拍号，也会明确提醒你检查段落转折。也可手动固定为 `3/4`、`6/8` 等。
- **调号**：WebUI 直接显示“降 A 大调 / F 小调”等调名。自动模式按实际音符内容选择调号，并用它重新拼写音名，以减少不必要的临时升降号。
- **五度圈数字**：这是 CLI 手动调号的简写，范围 -7 到 +7；负数表示降号数量，正数表示升号数量。例如 `-4` 是四个降号（A♭ 大调/F 小调共用），不是把所有音降低四个半音。
- **最小音符**：可选 `1/8`、`1/16`、`1/32`。
- **自动校正延迟**：估计并移除统一的演奏落后/提前量。
- **自动裁剪共同前导**：移除所有输入开头共有的空白；若要保留原始小节位置可关闭。
- **识别并保留琶音**：只把符合严格方向、时距与重叠条件的滚奏折叠成琶音和弦。
- **识别任意常见连音**：尝试当前重点比例 `2:3`、`3:2`、`4:3`、`5:3`、`5:4`、`6:4`、`7:4`、`7:8`、`9:8`、`11:8`、`12:8`、`13:8`，而不只是三连音。
- **识别倚音/倚音串**：把高置信度的主音前短音写成倚音；不明确的短音保持原样。
- **识别摇摆 / Shuffle**：仅在连续多个拍提供一致证据时采用区域性 Swing，不根据单个音对下结论。
- **保护颤音、波音等装饰**：当前自动转换范围是高置信度 ABAB 邻音颤音；其他装饰类型仍按普通量化输出并需人工复核。
- **弱起拍**：第一个完整强拍之前已经开始的、不满一整小节的开头。长度单位是四分音符拍，例如 4/4 中开头只有一个四分音符就填 `1`；这不是开头静音。自动模式会利用 MIDI 拍号事件识别常见弱起，也可手动覆盖。
- **标题**：写入乐谱标题。

## 命令行使用

最简单的高低音分配：

```powershell
midi-to-mscz --treble "vocal.mid" --bass "piano.mid" -o "score.mscz"
```

`--treble` 与 `--bass` 都可重复。每个文件固定占用目标谱表的一个声部；单个谱表最多四个输入 MIDI。位置参数默认使用 `--default-staff` 指定的谱表。简写形式共用 `--transpose-octaves`、`--transpose-semitones`、`--velocity-min` 和 `--offset-beats` 的默认值。

省略 `--output` 时，会在首个输入旁生成 `<首个文件名>_标准化.mscz`。

如果每个文件需要不同设置，重复使用：

```text
--input "路径|谱表|八度|额外移调半音|最低力度|时间对齐拍"
```

后五项可从右侧省略；谱表使用 `treble` 或 `bass`。包含空格、中文或日文的路径应整体加引号。例如：

```powershell
midi-to-mscz `
  --input "vocal.mid|treble|1|0|1|0" `
  --input "piano.mid|bass|0|0|1|0" `
  --bpm auto `
  --time-signature auto `
  --key-signature auto `
  --min-note 1/16 `
  --output "score.mscz"
```

常用开关：

```text
--bpm auto|数值
--time-signature auto|4/4
--key-signature auto|-7..7
--min-note 1/8|1/16|1/32
--no-auto-latency
--no-trim-common-leading
--no-arpeggios
--no-tuplets
--no-grace-notes
--no-swing
--no-ornaments
--pickup-beats 拍数
--title "标题"
--quiet
```

`--tuplets / --no-tuplets` 控制通用比例连音模型，并非只有三连音。倚音、区域性摇摆和快速装饰识别分别使用 `--grace-notes / --no-grace-notes`、`--swing / --no-swing`、`--ornaments / --no-ornaments`；这些识别默认开启，通常只需在某类语义明显误判时使用对应的 `--no-…` 关闭并比较结果。

查看全部参数：

```powershell
midi-to-mscz --help
```

## 输出与中间 MusicXML

最终输出只有一个 Piano part，使用高音与低音两个谱表，乐器音色为 Acoustic Grand Piano。生成过程先在输出目录旁的临时工作目录写 MusicXML，再调用 MuseScore 转为 `.mscz`；MuseScore 成功返回并通过基本结构检查后，目标文件才会被替换。默认会清理临时目录，不保留 MusicXML。

当前 WebUI 和 CLI 没有“保留 MusicXML”选项。需要调试或检查中间记谱内容时，可通过 Python API 设置 `keep_intermediate=True`；成功转换后会在 `.mscz` 旁保留同名 `.musicxml`：

```python
from midi_to_mscz import ConversionSettings, InputSpec
from midi_to_mscz.pipeline import convert

convert(
    [
        InputSpec("vocal.mid", staff="treble", transpose_octaves=1),
        InputSpec("piano.mid", staff="bass", velocity_min=1),
    ],
    "score.mscz",
    ConversionSettings(
        bpm=100,
        time_signature="4/4",
        smallest_note="1/16",
        keep_intermediate=True,
        # MuseScore 不在默认位置时也可填写：
        # musescore_path=r"D:\Apps\MuseScore 4\bin\MuseScore4.exe",
    ),
)
```

## 已知限制

- 这是面向谱面可读性的规则化工具，不是音频识别模型，也不会回听原曲；输入 MIDI 中的错音、漏音和错误音长无法凭空恢复。
- 固定延迟校正不能处理声部之间随时间变化的漂移。若两个 stem 的速度基准不同，应先在 DAW 中对齐或分段处理。
- 自动速度会保留稳定且持续的变化，但不会仅凭 MIDI 自动添加 `rit.`、`accel.`、fermata、cadenza 等文字语义；强 rubato 或自由拍仍需在 MuseScore 中复核。
- 自动调号目前可靠识别全曲初始大小调，并保留输入 MIDI 明确写出的后续调号变化；仅凭音符自动定位曲中转调仍需人工复核。
- 若输入完全没有可靠拍号事件，3/4、6/8、复合拍和自由节拍仅凭 MIDI 攻击时间可能有多种解释。程序此时保守使用 4/4 并提示，不会编造临时变拍。
- 倚音、琶音、比例连音、区域性摇摆、快速装饰和和弦判断都来自启发式证据，并非 MIDI 中无歧义的谱面信息。复杂或嵌套连音、装饰音与真实快速旋律、跨谱表内容和复节奏尤其需要人工检查。
- 当前只输出钢琴大谱表；原 MIDI 的乐器、歌词、踏板、弯音、控制器、音色、演奏法和大部分力度记号不会完整迁移。
- 输入文件被视为单声部语义：每次攻击持续到下一攻击，短 note-off 不产生中间休止；持续重叠统一视为踏板或混响并在下一攻击截断。若某个 MIDI 实际上确实包含两个独立旋律声部，应先拆成两个 MIDI 再导入。
- 每个 MuseScore 谱表最多四个声部，所以高音或低音谱表各最多接收四个 MIDI 文件；工具不会为了绕过限制而跨文件合并。
- 非法或缺失的 note-off、零/负时值音符会被忽略。移调后超出 MIDI 音域的音也无法输出。
- MuseScore 的 MusicXML 导入与自动排版会影响最终外观；不同 MuseScore 版本的分页、连线或声部布局可能略有差异。
- WebUI 的直接目录写入使用浏览器文件系统权限，需要最新版 Microsoft Edge 或 Google Chrome。应用只获得你手动选择的文件夹权限，不会读取或写入其他目录，也不会回退为浏览器下载。

## 故障排查

### Windows 安全中心或安全软件阻止启动脚本

请双击项目根目录的 `run_webui.pyw`，不要双击 `.whl` 安装包；入口由已安装且带签名的 `pythonw.exe` 直接运行，不经过 `.bat`、`cmd` 或 PowerShell。不要关闭实时防护，也不要把整个项目目录加入排除列表。若 `.pyw` 仍被阻止，请在安全软件的拦截记录中核对准确路径，只在确认确实指向本项目文件后允许该单个文件。若界面自身启动失败，程序会在项目目录生成 `startup_error.txt` 供排查。

### 提示“没有找到 MuseScore”

优先安装 MuseScore 4，并确认 `MuseScore4.exe` 存在。若使用便携版或自定义目录，请设置 `MUSESCORE_PATH`，或在 Python API 的 `ConversionSettings` 中填写 `musescore_path`。设置环境变量后需从同一个终端启动程序。

### 双击后没有打开 WebUI

WebUI 不依赖 Tcl/Tk。先检查是否已有浏览器标签页打开，并允许 Python 访问本机回环地址 `127.0.0.1`；它不需要公网权限。也可在项目目录运行 `py -3 -m midi_to_mscz`，终端会显示本地页面地址和具体错误。若浏览器被企业策略禁止自动打开，可复制该地址手动访问。

### 无法选择保存文件夹

请使用最新版 Microsoft Edge 或 Google Chrome 打开本地页面，并允许页面写入你选择的文件夹。Firefox 等未实现目录写入接口的浏览器无法使用此功能；程序不会自动改成下载。若同名文件已存在，覆盖前会再次确认。

### 提示“过滤后没有可输出的音符”

最低力度设得过高，或输入没有完整的 note-on/note-off 配对。先把阈值降为 `1`；若仍失败，用其他 MIDI 编辑器检查文件是否能正常播放。

### 谱面仍然很碎或休止符很多

先查看转换报告识别出的 BPM、拍号、调号与弱起，随后尝试把最小音符从 `1/32` 调粗为 `1/16` 或 `1/8`。若自动速度不合适，直接填写已知 BPM；若整轨统一错位，使用每文件“时间对齐”。特殊段落可分别关闭琶音、比例连音、倚音、摇摆或装饰保护做对照；命令行对应 `--no-arpeggios`、`--no-tuplets`、`--no-grace-notes`、`--no-swing`、`--no-ornaments`。

### 两个声部没有对齐

给其中一个文件设置小数“时间对齐（四分音符拍）”，例如 `-0.25` 表示提前十六分音符长度，`0.5` 表示延后八分音符长度。若开头空白本来有意义，请关闭“自动裁剪共同前导”。持续变大的错位不是固定偏移，工具无法自动修复。

### 音高不正确或音符消失

检查该文件的八度与半音移调。移调后低于 MIDI 0 或高于 127 的音会删除；超出钢琴 A0–C8 的音会保留并在报告中警告。人声 stem 常需要升高一个八度，但应以实际音域为准。

### 路径包含空格、中文或日文时 CLI 解析失败

给普通路径和整个 `--input` 规格加双引号。在 PowerShell 中，`|` 未加引号会被解释为管道，因此详细输入格式必须整体加引号。
